# NAS 部署说明（群晖 / 飞牛）

米家Web版以 Docker 容器方式运行在 NAS 上，7×24 常驻，不受"电脑关机就停服"限制。
群晖与飞牛都提供图形化的 Compose 部署界面，全程不需要敲命令行。

单实例只支持一个米家账号：打开页面登录后，所有设备都来自这个账号。
如果要让多个人各自登录自己的账号，需要每人跑一个容器（不同端口），本说明不涉及。

## 一、部署前准备

1. NAS 已安装 Docker（群晖叫 Container Manager，飞牛叫 Docker），并处于运行状态。
2. 在 NAS 的共享文件夹里建一个专用目录，例如：
   - 群晖：`/volume1/docker/mijia-web`
   - 飞牛：`/vol1/1000/docker/mijia-web`
3. 在该目录下再建一个空的子目录 `data`，用于存放登录态与数据。
   这个路径后面会填进 compose 的 volumes。

## 二、图形界面部署（群晖 Container Manager）

1. 打开 Container Manager → 左侧「项目」→ 点「新增」。
2. 填写项目信息：
   - 项目名称：`mijia-web`（英文，随意）
   - 路径：选第一步建的 `mijia-web` 文件夹
   - 来源：选「创建 docker-compose.yml」
3. 在编辑框里粘贴本项目根目录 `docker-compose.yml` 的内容。
4. 按实际情况改两处（详见文件内注释）：
   - `ports`：左边端口改成 NAS 上空闲的端口，如 `9080:8765`
   - `volumes`：左边路径改成第一步建的 `data` 目录真实路径
5. 勾选「创建项目后立即启动」，点「完成」。
6. 等待镜像拉取与容器启动完成，状态显示「运行中」即可。
7. 浏览器打开 `http://NAS的IP:端口`（如 `http://192.168.1.10:9080`）。

## 三、图形界面部署（飞牛 fnOS）

1. 打开飞牛「Docker」→ 左侧「Compose」→ 点「新增项目」。
2. 填写项目信息：
   - 项目名称：`mijia-web`
   - 路径：选第一步建的 `mijia-web` 文件夹（右键文件夹「详细信息」可复制原始路径）
   - 来源：选「创建 docker-compose.yml」
3. 粘贴 `docker-compose.yml` 内容，同样改 `ports` 与 `volumes` 两处。
4. 勾选「创建项目后立即启动」，点「确定」。
5. 切到「容器」页，确认 `mijia-web` 容器处于运行中。
6. 浏览器打开 `http://NAS的IP:端口`。

若拉取镜像失败或很慢，飞牛可在「Docker → 镜像仓库 → 设置 → 加速源」添加国内加速源；
群晖可在「Container Manager → 设置 → 镜像源」配置。这是 NAS 拉取 GitHub 镜像的常见问题，
与程序本身无关。若加速源仍不可用，可改用"本地构建"方式（见第六节）。

## 四、登录使用

1. 打开页面后点「登录」，用手机米家 App 扫码即可，无需输密码。
2. 登录态保存在挂载的 `data` 目录里（`mi.token`），容器重建、NAS 重启都不会掉登录。
3. 首次进入设备状态可能需要几秒同步，页面会显示「数据正在加载中」，加载完成自动消失。

## 五、公网访问配置（可选，按需开启）

默认只建议在局域网内使用。需要公网访问时，逐项配置：

1. 设置访问密码（强烈建议）：把 compose 里这两项填上，两项都填才生效。
   ```
   MIHOME_ACCESS_USER: "admin"
   MIHOME_ACCESS_PASSWORD: "换成一个长随机密码"
   ```
   开启后任何访问都需要输入密码，否则任何人扫到端口就能开关你家设备。

2. 设置来源白名单：如果你用域名或 DDNS 访问，把域名填进去（多个用逗号分隔）：
   ```
   MIHOME_ALLOWED_ORIGINS: "mi.example.com,www.example.com"
   ```
   写接口只接受这些主机名发来的请求，防止跨站攻击。仅用 IP 访问时可留空。

3. 改完 compose 后，在 NAS 上「重新部署 / 更新」项目使配置生效。

4. 推荐做法：不要在路由器上直接把 8765 端口映射到公网。
   更安全的方案是 NAS 上装反向代理（如 Nginx Proxy Manager）+ HTTPS 证书，
   由反代对外提供 443，再转发到容器的 8765，并限制来源 IP。

5. 安全边界提醒：本项目是单账号实例，公网部署只适合自己在外访问自己的账号；
   不要把它当作对外提供服务的多用户平台。

## 六、升级与回滚

容器内禁用了应用内升级（那会写容器可写层，重建后版本回退，不一致）。
正确升级方式：

1. 修改 `docker-compose.yml` 里 `image` 的标签版本号，例如 `:0.2.1` 改成 `:0.3.0`。
2. 在 NAS 的 Compose 项目页点「重新部署 / 更新」，它会自动拉取新镜像并重建容器。
3. 数据都在 `data` 卷里，重建后无需重新扫码登录。

回滚：把 `image` 标签改回旧版本号，再重新部署一次即可。

如需本地构建镜像（当 GHCR 拉不动时）：把源码整个目录上传到 NAS，
在 compose 里把 `image:` 那行替换为 `build: .`，再重新部署。
首次构建会慢一些（要下载 Python 基础镜像和依赖），之后靠缓存会快。

## 七、注意事项

- `MIHOME_HOST`、`MIHOME_PORT`、`MIHOME_NO_BROWSER`、`MIHOME_DATA_DIR`
  这四项在容器内保持默认即可，不要改。
- 数据卷 `./data` 一定要映射到 NAS 的真实持久化目录，否则容器删除后登录态会丢。
- 米家 token 属于敏感凭据，`data` 目录不要共享到公网或放进公开网盘。
- 摄像头实时画面需要额外的取流中继（ffmpeg + go2rtc），当前容器未集成，
  页面只提供设备能力探测，不保证出画面。
